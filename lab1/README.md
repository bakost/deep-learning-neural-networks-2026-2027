# jacobi-eigen — метод Якоби для симметричной проблемы собственных значений

Лабораторная работа №1. Пакет вычисляет **все** собственные числа и
собственные векторы вещественной симметричной матрицы методом вращений
Якоби (Карл Густав Якоби, 1846).

```python
import numpy as np
from jacobi_eigen import jacobi_eigh

A = np.array([[4.0, 1.0, 0.0],
              [1.0, 3.0, 1.0],
              [0.0, 1.0, 2.0]])

result = jacobi_eigh(A)
print(result.eigenvalues)        # [1.267949 3.       4.732051]
print(result.eigenvectors)       # собственные векторы — по столбцам
print(result.residual_norm(A))   # 1.8e-15 — невязка ||A V - V L||
```

## Возможности

- **Два интерфейса** — функция `jacobi_eigh()` для разовых вызовов и класс
  `JacobiEigensolver` для настраиваемого, переиспользуемого решателя.
- **Три реализации шага вращения** (`kernel=`), дающие численно один и тот
  же результат:
  | Ядро | Сложность шага | Что это |
  |---|---|---|
  | `scalar` | $O(n)$ | буквальный перевод формул методички на Python |
  | `vectorized` | $O(n)$ | те же формулы срезами NumPy (по умолчанию) |
  | `matrix` | $O(n^3)$ | честное умножение $P^T A P$ на матрицу Гивенса |
- **Три стратегии выбора зануляемого элемента** (`strategy=`): `cyclic`,
  `max`, `round-robin` (последняя — порядок, пригодный для распараллеливания).
- **Полная валидация входа** с конкретными сообщениями об ошибках.
- **Контракты** (предусловия, постусловия, инварианты) — своя реализация
  Design by Contract, отключаемая одним флагом.
- **Гарантия завершения**: зацикливание невозможно, лимит итераций жёсткий.
- **CLI** `python -m jacobi_eigen` с режимами сверки и сравнения скорости.

## Использование

### Функциональный интерфейс

```python
from jacobi_eigen import jacobi_eigh

result = jacobi_eigh(A, tol=1e-12, kernel="vectorized", strategy="cyclic")
```

### Объектный интерфейс

Удобен, когда одни и те же настройки применяются к множеству матриц:

```python
from jacobi_eigen import JacobiEigensolver

solver = JacobiEigensolver(tol=1e-14, kernel="scalar", strategy="max")
for matrix in matrices:
    result = solver.solve(matrix)     # или solver(matrix)
```

### Параметры решателя

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `tol` | `1e-12` | требуемая точность |
| `tol_mode` | `"relative"` | порог относительно $\|A\|_F$ либо абсолютный |
| `kernel` | `"vectorized"` | реализация шага вращения |
| `strategy` | `"cyclic"` | порядок выбора зануляемого элемента |
| `max_sweeps` | `100` | лимит итераций (защита от зацикливания) |
| `compute_eigenvectors` | `True` | вычислять ли матрицу $V$ |
| `sort` | `"asc"` | порядок собственных чисел (`asc`/`desc`/`None`) |
| `symmetrize` | `True` | приводить вход к строго симметричному виду |

### Объект результата

```python
result.eigenvalues              # собственные числа, массив (n,)
result.eigenvectors             # собственные векторы по столбцам, (n, n)
result.rotations                # сколько выполнено вращений
result.sweeps                   # сколько выполнено свипов
result.off_norm                 # достигнутая норма внедиагональной части
result.converged                # достигнут ли критерий остановки
result.elapsed                  # время счёта, секунды

result.residual_norm(A)         # ||A V - V L||_F
result.orthogonality_error()    # ||V^T V - I||_F
result.reconstruction_error(A)  # ||A - V L V^T||_F
result.trace_error(A)           # |sum(L) - tr(A)|
result.reconstruct()            # V L V^T
result.sorted("desc")           # копия с другим порядком
result.summary(A)               # человекочитаемый отчёт
result.to_dict()                # представление для JSON
```

## Обработка ошибок

Все ошибки пакета наследуются от `JacobiError`, поэтому одного обработчика
достаточно:

```python
from jacobi_eigen import JacobiError, jacobi_eigh

try:
    result = jacobi_eigh(user_input)
except JacobiError as exc:
    print("Ошибка:", exc)
```

| Ситуация | Исключение | Пример сообщения |
|---|---|---|
| не квадратная | `NotSquareError` | `Матрица должна быть квадратной, получена матрица 2x3.` |
| не симметричная | `NotSymmetricError` | `A[0, 1] = 2.0, A[1, 0] = 3.0, расхождение 1 превышает допуск 4e-10` |
| комплексная | `NotRealError` | `элемент A[0, 1] = 2j имеет ненулевую мнимую часть` |
| `NaN` / `inf` | `NotFiniteError` | `Матрица содержит неконечные значения (2 шт.): A[0, 1] = nan` |
| не массив чисел | `NotArrayLikeError` | `Матрица содержит строку 'a' вместо числа.` |
| не двумерная | `NotTwoDimensionalError` | `получен массив размерности 1 с формой (3,)` |
| пустая | `EmptyMatrixError` | `Матрица пуста (форма (0, 0))` |
| плохой параметр | `InvalidParameterError` | `tol должен быть строго положительным, получено -1e-09` |
| не сошёлся | `ConvergenceError` | `не сошёлся за 1 свип(ов) (190 вращений)` |
| нарушен контракт | `ContractViolation` | `Нарушено предусловие функции ...` |

Иерархия устроена так, что исключения одновременно являются привычными
`ValueError` / `TypeError` / `RuntimeError`.

## Контракты

В Python нет встроенного механизма контрактов, поэтому в пакете есть
`jacobi_eigen.contracts` — минимальный аналог `icontract`/Eiffel:

```python
from jacobi_eigen import require, ensure, invariant

@require(lambda n: n >= 0, "n неотрицательно")
@ensure(lambda result: result >= 1, "факториал не меньше единицы")
def factorial(n):
    return 1 if n == 0 else n * factorial(n - 1)
```

Контрактами покрыты вычисление параметров поворота (например, постусловие
$\cos^2\varphi + \sin^2\varphi = 1$), валидация входа и состояние решателя
(инвариант «`max_sweeps > 0`, значит цикл заведомо конечен»).

Проверки отключаются тремя способами:

```bash
python -O program.py                    # стандартный флаг оптимизации
JACOBI_CONTRACTS=0 python program.py    # переменная окружения
```
```python
from jacobi_eigen import contracts_disabled
with contracts_disabled():
    ...
```

Контракты стоят примерно **×1.9** ко времени счёта, поэтому в замерах
производительности они отключаются.

## Производительность

Замеры на случайных симметричных матрицах (полные таблицы —
[docs/benchmarks.md](docs/benchmarks.md)):

| n | `scalar` | `vectorized` | `matrix` | `numpy.linalg.eigh` |
|---|---|---|---|---|
| 10 | 4.8 мс | 6.0 мс | 4.8 мс | 0.03 мс |
| 40 | 328 мс | 182 мс | 163 мс | 0.57 мс |
| 80 | 3028 мс | 711 мс | 1473 мс | 0.91 мс |
| 160 | — | 3152 мс | — | 2.77 мс |

Выводы:

- **NumPy быстрее в сотни-тысячи раз.** Это ожидаемо: `numpy.linalg.eigh`
  вызывает LAPACK (`dsyevd`) — скомпилированный код, использующий приведение
  к трёхдиагональному виду, блочные операции BLAS-3 и несколько потоков.
  Метод Якоби принципиально выполняет больше арифметики: он делает $O(n^2)$
  вращений за свип и несколько свипов.
- **Векторизация даёт выигрыш только с ростом $n$.** При $n = 10$ скалярное
  ядро даже быстрее: накладные расходы вызова NumPy на коротких срезах
  превышают пользу. При $n = 80$ векторизованное ядро уже вчетверо быстрее.
- **Матричное ядро не так безнадёжно, как кажется.** Формально оно $O(n^3)$
  на шаг против $O(n)$, но два умножения выполняет BLAS, тогда как скалярное
  ядро крутит цикл в интерпретаторе Python. На средних размерах BLAS
  выигрывает; на больших асимптотика берёт своё.
- **Стратегия `max` требует вдвое меньше вращений** (12 373 против 24 424 при
  $n = 80$), но поиск максимума стоит $O(n^2)$ на шаг и съедает выигрыш.

Точность при этом не уступает эталону: расхождение с `numpy.linalg.eigvalsh`
составляет $10^{-14}$–$10^{-15}$ относительно нормы матрицы.

Запуск замеров:

```bash
python benchmarks/benchmark.py --sizes 10 20 40 80 --repeats 3
```

### Замеченные неточности методички

При реализации обнаружились два места, где буквальное следование тексту даёт
неверный результат; оба разобраны в [docs/theory.md](docs/theory.md):

1. **Формула (19)** вычитает $(A^i_{pq})^2$, хотя сумма $S$ определена по всем
   внедиагональным элементам, а одно вращение зануляет сразу два симметричных
   элемента. Корректно: $S_{i+1} = S_i - 2(A^i_{pq})^2$.
2. **Случай $C^i = 0$** (равные диагональные элементы) не покрыт формулой (9)
   — в реализации он отнесён к ветви $C \ge 0$, что даёт поворот на $45^\circ$.
